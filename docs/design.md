# Skill 发布指南设计

用户已确认建立独立项目并开始编写。第一版版本为 `1.0.0`，采用自有维护仓库与用户级安装副本分离的结构。

## 目标

给另一个代理一个已完成的 skill 和用户选择的平台后，它能判断应提交 GitHub 仓库/子目录链接、ZIP、CLI 包还是目录 PR，准备正确范围的材料，在已授权范围内执行，并根据证据区分已接收、待审、已公开、失败与未知。

## 包结构与边界

`skills/skill-publishing-guide/` 包括 `SKILL.md`、`agents/openai.yaml` 与按平台拆分的 `references/`。主入口以中文编写，description 保留可检索的英文关键词；正常允许隐式选择。

主入口只保留意图、路由和共同约束。当前参考页覆盖 GitHub、skills.sh、腾讯 skillhub.cn、独立 skillhub.club、Skillstore、ClawHub、Agensi 和 VoltAgent，另有打包、结果核验、记录模板及来源维护。当前清单为 8 个渠道；用户另行要求调查其他平台时重新核验实际入口，不将未知状态写成已支持自动发布。

运行包不包含自动上传脚本、维护工具或真实提交记录。常用 CLI 命令只在相关平台参考中给出，执行前核对本机帮助与目标。暂不实现跨市场 API 封装。

## 共同规则

- 用户只问方法或要求准备时，执行到相应范围；不因为进入此 skill 就创建公开仓库、登录或发布。
- 复用会话中已明确且适用的授权。确需新的用户输入时先完成独立准备，按会话通知规则提出具体请求；不把准备工作卡在缺少登录上。
- 唯一发布单元为用户指定的 skill。区分 repo URL、固定 ref 的 tree URL 与 raw 文件 URL；提交入口接受 URL 不足以证明导入范围。
- ZIP 的根层级按目标平台当前要求选择。支持描述带单个同名目录与直接 SKILL.md 根两种形式；不能把一种写成所有平台通用规范。
- 版本、许可、语言和可见性沿用已确定值。检测已有发布、同版本冲突或请求结果未知时先核验；不通过自动改名/升版/重试掩盖不确定状态。
- GitHub 凭据不发送到第三方镜像，不在日志/包中保存凭据。平台证书错误或入口失效保留核验限制，不绕过认证/访问控制或改用不明工具。
- 提交返回、后台审核和公开版本分开记录；核对来源提交、skill 路径、作者版本、平台修订和实际产物。各平台术语按一手证据映射，保留原始状态。

## 维护与证据

参考现成发布技能的组织方式，使用独立表述；一手资料、平台界面观察、作者历史实操和未核验信息分别标识。第三方框架的思想来源记录在维护文档，不复制其个人配置或流程缺陷。

复用 `software-testing-router` 已验证的离线校验器与备份安装器，仅适配目标名；新仓库可独立运行，不引用兄弟目录。依赖固定版本。初始本地标签和 ZIP 由干净验证提交生成，安装到 `~/.agents/skills/skill-publishing-guide/`。

## 验证

结构验证检查 metadata、包内链接与文件清单；工具检查实际预览、复制、幂等及备份。行为验证使用受控多 skill 仓库、发布回执、版本冲突与不安全第三方示例，让独立代理完成准备/核验，比较无新技能的基线和有技能的结果。所有行为评估离线或只读，不使用真实凭据、发布或付费动作。基线若本已正确，如实记录，不宣称技能带来未测量的提升。

完成标准包含可读可用的正文、平台证据边界、独立评估和必要工具检查、用户级副本一致性、提交/合并与分支清理。
